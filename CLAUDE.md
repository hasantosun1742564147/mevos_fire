# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

MEVOS Fire (`mevos_fire`) is a Flutter app ("Yangın Hesap ve Standart Rehberi" — fire-safety
calculation and standards guide) for iOS/Android/desktop/web. UI strings and internal
identifiers are largely Turkish; user-facing text is localized into Turkish/English/German.

## Commands

```
flutter pub get                 # install dependencies
flutter run                     # run on a connected device/emulator
flutter analyze                 # static analysis (uses analysis_options.yaml + flutter_lints)
flutter test                    # run all tests
flutter test test/widget_test.dart   # run a single test file
flutter gen-l10n                # regenerate lib/l10n/app_localizations*.dart from .arb files (see l10n.yaml)
flutter build apk / appbundle   # Android release build
flutter build ios --no-codesign # iOS build without signing (used in CI)
flutter build ipa               # iOS signed IPA
```

iOS CI builds are defined in `codemagic.yaml` (unsigned release build + ad hoc IPA build,
triggered on push to `main`).

## Architecture

**Almost the entire app lives in a single file: `lib/main.dart` (~19.5k lines).** There is no
feature-folder structure — screens, widgets, models, and business logic for every calculation
module are all defined here as top-level classes, roughly in the order a user would encounter
them. When navigating this file, search for `^class ` to jump between screens/widgets rather
than trying to read it top-to-bottom. Supporting files outside `main.dart` are limited to:

- `lib/l10n/app_localizations*.dart` — generated by `flutter gen-l10n` from `.arb` files in
  `lib/l10n/`; do not hand-edit these, edit the `.arb` sources and regenerate instead.
- `lib/l10n/building_type_translations.dart` — a hand-maintained lookup table (`buildingTypeTranslations`)
  mapping building-type keys to localized display names, used via `_binaGorunenAd()`.

### App flow

- `main()` initializes `SharedPreferences`, restores the saved locale (default `tr`), and runs
  `MevosFireApp`.
- `_StartupEkrani` checks for a saved `jwt_token` in `SharedPreferences` and calls
  `$kApiBase/api/auth/me.php` to validate the session before routing to `GirisSayfasi` (login)
  or straight into the app.
- `GirisSayfasi` handles login against `$kApiBase/api/auth/login.php` and includes rate-limit
  handling (`_rateLimitBaslat`, a countdown timer disabling repeated login attempts) and a
  "demo mode" path (`AnaSayfa(demoModu: true)`) that lets users explore with certain modules
  gated off (`demoIzinli` flag per module tile).
- `AnaSayfa` is the module dashboard. Each module tile checks subscription/permission state via
  `hasActiveFirePerm()` (permissions come from the backend as a `perms` map with `fire` /
  `fire_activatedAt` fields — annual vs. lifetime ("omur") entitlements) and demo-mode gating
  before allowing navigation.
- Backend base URL is `kApiBase` (`https://www.mevos.com.tr`); auth/account endpoints live
  under `/api/auth/*.php` (`login`, `me`, `delete-account`, etc.), and a separate endpoint
  (`fire_version.php`) is polled for update checks against `kAppVersion`.

### Calculation modules

Each fire-safety calculation is its own top-level `StatefulWidget` in `main.dart`, e.g.
`YanginYukuSayfasi` (fire load), `DavlumbazSondurme` (kitchen hood suppression), `GazliSondurme`
(gas suppression systems), `BaskiMakinesiSondurme` (printing press suppression), `PanoIciSondurme`
(electrical panel suppression), `DumanAlgilama` / `DumanKontrol` (smoke detection/control),
`LityumPilYangini` (lithium battery fire), `SprinkleSistemi` (sprinkler hydraulics — the largest
module, includes pump/foam/sprinkler-class sub-calculations). Each module tends to have its own
private model classes, result-row widgets, and picker bottom sheets defined immediately
above/below it in the file — when modifying a module, look for its private helper classes
nearby rather than assuming shared utilities.

`StandartArama` / `StandartRehberi` provide search/browsing over the standards database, which
is loaded from locale-specific JSON assets (`assets/standartlar_db.json` for Turkish,
`standartlar_en.json`, `standartlar_de.json`) — flat maps of standard code → `{ad, kategori,
aciklama}`.

### AI assistant integration

Despite the `geminiChat()` function name and API endpoint (`generativelanguage.googleapis.com`,
Gemini), some UI elements reference "Grok" (e.g. `_GrokButon`) — check which is actually wired
up before assuming either name is authoritative. The Gemini API key is user-supplied and stored
locally via `SharedPreferences` (`gemini_api_key`), prompted for through `_geminiApiAl()` /
`_geminiApiDiyaloguGoster()`. Chat UI lives in `AiSohbetSayfasi`; API key management UI is
`ApiAyarlariSayfasi`.

### Local persistence

`SharedPreferences` is used throughout for: locale (`app_locale`), auth (`jwt_token`), the
Gemini API key, and saved projects/calculation results (see `_Proje` / `ProjeServisi` and
`KayitliProjeler` for the "saved projects" feature that persists module inputs/outputs for
later review).

### Localization

- Source of truth is the `.arb` files under `lib/l10n/` (template: `app_tr.arb`, per
  `l10n.yaml`); run `flutter gen-l10n` after editing them.
- `_localeNotifier` (a global `ValueNotifier<Locale?>`) drives locale switching at runtime;
  `_setAppLocale()` updates it and persists the choice.
- Building-type display names are a separate hand-written map in
  `building_type_translations.dart`, not part of the `.arb` files.
